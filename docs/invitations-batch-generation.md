# 邀请函批量生成

## 使用入口

专属邀请函 → 选择已发布的会议 → 邀请记录 → 批量生成。

- 粘贴名单：一行一个姓名，也可粘贴 Excel 多列数据。
- 上传表格：Excel（XLSX / XLS）、CSV / TSV，最大 5MB；自动识别姓名、单位和称谓列，可手动调整工作表、跳过表头行数和列映射。
- 公开名单：从已发布名单中多选嘉宾，或在不超过 200 人时全选。草稿中的未发布名单不参与匹配。
- 每批 1–200 位。只读取姓名、称谓和用于匹配的单位，不把手机号等其他列提交到后台。未指定称谓列时使用默认称谓；称谓列中的空值表示不加称谓。
- 预览会提示缺少姓名、超长字段和同名待确认项。完全相同的导入行去重并显示数量；有问题的行可移除后提交，不会悄悄丢掉。
- 按姓名匹配公开名单，同名时可结合单位匹配；仍有歧义时必须人工选择。没有公开名单位置的受邀人仍可生成邀请，但不会虚构名单位置。

## 生成与导出

确认名单后点击一次生成，后台在一个事务中处理整批。失败不留下部分新记录；网络中断可以重试同一批次，不会重新生成已成功的邀请。

当前账号、当前会议中姓名、称谓和名单位置相同的有效邀请会复用原链接。不会读取或复用其他工作人员的邀请，也不会自动启用已停用邀请；重试批次里曾创建的邀请若后来被修改或停用，须重新准备。

生成后可以复制全部或导出 CSV 链接表格。CSV 对表格公式起始字符做转义；导出文件包含个人邀请链接，应只交给负责邀约的工作人员。邀请链接仍使用观潮会集域名，并引用会议的最新已发布内容。

## 权限与验收

- 后台接口 `POST /api/admin/invitations/campaigns/:id/recipients/batch` 要求登录以及 `invitation:view`、`invitation:write`，另需有会议授权。沿用原权限，不赋予内容编辑、发布或全员记录权限。
- 仍需先发布会议。未发布时批量入口不可用；请求过程若发布版本改变，整批拒绝并要求重新确认。
- 人工验收：分别用粘贴、表格和公开名单准备两三名嘉宾；检查同名确认，生成和导出后打开各自链接，确认姓名独立、会议内容一致；再提交相同名单应复用自己的有效邀请。
- 本次不自动创建生产邀请、不改变原会议内容、支付、订单或报名逻辑，也不新增数据表和数据库迁移。
