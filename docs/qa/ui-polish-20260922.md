# Homepage and Personal Center UI Polish

Date: 2026-09-22

## Scope

- Homepage: dismissible floating notice for new unread messages only. No empty
  notice for guests, zero unread messages, or a previously dismissed batch.
  Dismissal is scoped to the user, bounded to 100 IDs, and does not mark messages
  read or delete them. New unread IDs can trigger a new notice.
- Personal center: rename attendance entry to "My Attendance" in Chinese.
  Remove public claim entry from both personal center and attendance pages.
- Private invitations: admin generates an invitation, then an expiring WeChat
  URL Link to the fixed claim page. No manual public token input. Confirmation
  retains the existing verified-phone, active-registration, and single-use
  checks. Link retries do not generate another invitation or change attendees.
- Conference list: compact horizontal rows with an aspect-fit thumbnail,
  two-line title, one-line date/location and whole-row action. Summaries are
  one line when explicitly enabled, hidden by default. Preserve configured content visibility,
  ordering/filtering and business action. Scope the layout to conference-list;
  do not alter conference-tabs, pricing or remaining-seat logic.
- Profile: native full-width edit action avoids mini-program component-host
  grid placement problems. Name can wrap; phone is on its own line. Retain gold.

## Release Notes

No schema migration, new environment secret, payment change, or production-data
mutation. URL Link generation uses existing server-side mini-program credentials
and requires admin registration-write AND member-write permissions. Expired,
consumed, rebound, checked-in or refund-in-progress claims are rejected before
calling WeChat. No raw upstream error or invitation token is logged.

The destination page must exist in the published Mini Program. A missing page,
unpublished app or missing URL Link capability produces an actionable error,
not a fabricated link. Verify with a designated test invitation after release.
Never use a real guest record simply to test link generation: the existing
invitation operation changes attendee binding and rotates the credential.

API contract checked against [WeChat generateUrlLink documentation](https://developers.weixin.qq.com/miniprogram/dev/server/API/qrcode-link/url-link/api_generateurllink.html).

admin http://127.0.0.1:5194/. They are not production data or real invitation links.
