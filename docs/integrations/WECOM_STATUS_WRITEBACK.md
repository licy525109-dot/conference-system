# 企微智能表状态回写

## 范围与数据归属

- 在现有宽表连接中增加独立的状态回写开关，旧连接默认关闭。
- 支持智能机器人 API 和自建应用 API；Webhook、旧双表模式暂不支持此回写。
- 系统数据库中的参会人签到、报名状态和订单支付/退款结果是唯一来源。表内编辑不会改变订单、退款或参会资格。
- 会务安排继续从智能表读取为草稿，由管理员确认发布；状态回写不自动发布安排。
- 不改变签到、支付、退款事务；复用现有后台同步任务，失败在下一轮重试，现场签到不依赖企微是否可用。

## 配置

1. 在原表添加专用的文本列：签到状态、签到时间、系统报名状态、系统订单号、付款状态、付款时间、退款状态。可只配置需要的列；时间列也使用文本，显示北京时间。
2. 后台进入“嘉宾会务安排 > 智能表连接”，识别现有表，保留原嘉宾匹配和现场事项规则。
3. 在“系统状态回写”中开启开关并选择对应文本列。同一列不能映射多个状态，也不能覆盖姓名、手机号、会务安排或报名写入列。
4. 启用自动同步，保存后检查连接。检查只读取元数据，不写测试行；实际写权限需要首次同步验证。
5. 点击“立即同步”，核对最近同步中的回写数量及错误。现场建议选择 30 秒间隔；后台扫描间隔为 15 秒，实际延迟还包括接口请求时间，不保证秒级即时。

## 匹配与安全

- 只更新已保存绑定的原表记录，不为状态同步创建新行。
- 优先核对唯一的系统参会人 ID；没有 ID 时要求手机号，或姓名加公司，在系统与原表两边都唯一。冲突 ID 不降级为手机号匹配。
- 多人共用手机号时应配置系统参会人 ID；一个参会人一行，不能将整单多个名额压在一行。
- 不同会议应使用独立子表；检测到同一文档子表被多个会议同时启用状态回写时停止同步，防止相互覆盖。
- 行被删除、身份不一致、重复绑定、列被删除或改为公式等非文本类型时，不猜测写入；同步记录提示待处理，修正后重试。
- 只更新发生变化的指定单元格；无增量计数，重复扫码不重复累计。撤销签到会清空签到时间。
- 已绑定的取消/退款记录仍参与回写，避免原表保留旧状态。硬删除的报名或参会人不在本功能同步范围内，不会删除原表行。
- 付款、退款按订单结果标注，同单多人可有相同订单号；不复制订单金额，避免按嘉宾行求和重复统计收入。
- 部分退款、退款处理中、全额退款分别显示；免付费邀请不标作实付成功。状态同步只覆盖已有报名记录，不创建未付款订单行。

## 验收

1. 在测试表绑定两位嘉宾，确认关闭回写时不写入；开启后只改选定列。
2. 一位扫码签到，等待同步，原表显示已签到及北京时间；另一位保持未签到。
3. 重复扫码与重复同步不重复写入；撤销签到后恢复未签到并清空时间。
4. 已确认的付款、部分退款、全额退款分别核对；智能表手填已支付不改变系统，下一轮被真实状态覆盖。
5. 同单多人分别签到，错误 ID/重复手机号不误写；已有房间、桌号、备注保持不变。
6. 模拟企微失败，本地签到仍成功；恢复权限/网络后下一轮修复状态，最近同步显示结果。

本地自动化测试不能替代真实企微文档写权限、真实字段类型与现场设备验收。生产启用前先用测试表核对。
