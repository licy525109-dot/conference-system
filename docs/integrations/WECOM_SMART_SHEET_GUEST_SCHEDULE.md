# 企微智能表嘉宾会务安排

## 数据边界

- 系统数据库是报名和发布状态的唯一可信来源。
- 企微智能表负责运营编辑，不直接向嘉宾端展示。
- 每次同步只更新草稿；后台点击“仅发布”或“发布并提醒”后，小程序才读取新的冻结快照。
- 企微来源事项必须回到智能表修改；后台手工新增事项才可在后台编辑，避免双向修改互相覆盖。
- 删除智能表行不会自动删除已发布安排，避免误操作；需在后台归档。

## 接入模式

系统支持两种连接方式。已经在其他企业主体中维护的智能表，优先使用
`Webhook / 自动化`；只有应用和文档属于同一可授权主体时，才使用自建应用 API。

### Webhook / 自动化（推荐用于现有表）

该模式不读取整张表，也不要求把现有表迁移到网站所属企业微信：

1. 在原智能表的“自动化 > 接收外部数据”中生成一个 Webhook URL，并复制平台提供的示例 JSON。
2. 后台保存 Webhook URL 和示例 JSON。系统只在有新报名或报名信息变化时向该 URL 写入。
3. 原智能表再配置一条“记录新增或字段变化 > 发送 HTTP 请求”的自动化，将当前行推送到后台生成的回调地址。
4. 后台把回传行匹配到参会人并生成会务安排草稿。管理员仍需点击“仅发布”或“发布并提醒”，嘉宾端才会看到。

数据归属固定如下：

- 报名身份、报名编号、票种等字段由系统写入。
- 工作坊、晚宴、分享、彩排等会务字段由原智能表维护并回推。
- Webhook URL 和自动化回调令牌均按密钥处理，服务端加密保存，不写入日志，也不返回明文 Webhook URL。
- 智能表 Webhook 只能更新由同一个 Webhook 创建的行。系统会保存返回的 `record_id`，因此能更新自己创建的报名行；不会修改原表中人工创建的历史行。
- 回调只接受最多 100 行 JSON 数据，按系统参会人 ID、手机号、姓名加公司依次匹配，无法唯一匹配的行会记录错误，不会猜测绑定。

### 自建应用 API（兼容）

该模式使用 CorpID、应用 Secret 和智能表 API 定时读写，适合自建应用与智能表处于同一企业主体、且应用已获得文档对象权限的情况。原来的双子表和现有宽表配置继续保留。

## 企业微信准备（自建应用 API）

1. 在企业微信管理后台创建自建应用，并允许该应用访问目标智能表格。
2. 在一个智能表格文档内创建两个子表：“报名嘉宾”和“嘉宾事项”。
3. 将自建应用的 CorpID、AgentID 和 Secret 配置到系统后台“企微接入配置”。Secret 只保存在服务端加密字段中。
4. 从文档和子表链接/API 获取 `docid`、报名嘉宾 `sheet_id`、嘉宾事项 `sheet_id`。

## 报名嘉宾子表

以下列均使用“文本”类型。系统只写入，不要求运营回填：

`系统参会人ID`、`报名编号`、`会议ID`、`会议名称`、`姓名`、`手机号`、`公司`、`职务`、`票种`、`报名状态`、`系统同步时间`。

## 嘉宾事项子表

建议字段：

| 列名 | 类型 | 用途 |
| --- | --- | --- |
| `系统事项ID` | 文本 | 系统回写，运营不要修改 |
| `系统参会人ID` | 文本 | 从报名嘉宾表复制，首选匹配键 |
| `姓名` / `手机号` | 文本 | 便于运营识别；手机号可作为唯一匹配兜底 |
| `事项类型` | 单选或文本 | 工作坊、晚宴、分享演讲、彩排、接待、其他 |
| `事项名称` | 文本 | 必填 |
| `开始时间` / `结束时间` | 日期时间 | 开始时间必填 |
| `地点` / `角色` / `桌号` | 文本 | 现场安排 |
| `是否桌长` | 复选框 | 晚宴桌长身份 |
| `分享主题` / `备注` | 文本 | 嘉宾可见补充信息 |
| `后台发布状态` / `后台同步时间` | 文本 | 系统回写，运营不要修改 |

## 系统配置与验收

1. 后台进入“会议管理 > 嘉宾会务安排”，选择会议并打开“智能表连接”。
2. 填写文档 ID 和两个子表 ID，先保存，再点击“检查连接”。
3. 检查通过后启用自动同步，点击“立即同步”完成首次联调。
4. 在嘉宾事项子表新增一行，等待同步；后台应出现“待首次发布”。
5. 点击“仅发布”，使用该报名账号打开“小程序 > 我的报名 > 查看会务安排”核对。
6. 再修改智能表中的地点，后台应显示“有待发布变更”，嘉宾端仍保持旧地点；再次发布后才更新。

若检查或同步返回 `851003` / `no authority`，说明自建应用对该文档没有智能表 API 权限。请调整文档协作权限和应用可见范围；若文档属于另一个企业主体，请改用 `Webhook / 自动化`。

## Webhook / 自动化验收

1. 在连接弹窗选择 `Webhook / 自动化`，粘贴原表链接、接收外部数据 Webhook URL 和示例 JSON。
2. 点击“识别示例字段”，确认页面展示的字段与原表一致，并完成嘉宾身份及事项字段映射。
3. 保存并启用后点击“检查连接”。该检查只验证 URL 格式、示例字段和映射，不会向原表写入测试行。
4. 完成一次真实报名，原表应新增一行；重复同步不得新增第二行。
5. 在原表自动化中配置后台展示的回调地址，按页面示例发送 `record_id`、`update_time` 和当前行 `values`。
6. 修改工作坊或晚宴字段后，后台应出现“待首次发布”或“有待发布变更”；小程序在管理员发布前保持旧内容。
7. 使用错误回调令牌、缺少身份字段、超过 100 行或无法唯一匹配的请求，均应被拒绝或记录为失败，且不能发布嘉宾内容。

## 微信提醒

1. 在微信公众平台选择订阅消息模板，并记录模板 ID 与关键词字段名。
2. 后台通知中心创建代码为 `GUEST_SCHEDULE_UPDATED` 的微信订阅模板，配置模板 ID、页面 `pages/registrations/schedule` 和 `wechatData` 字段映射后启用。
3. 服务端启用 `NOTIFICATION_CENTER_ENABLED` 和 `WECHAT_SUBSCRIBE_MESSAGE_ENABLED`，并配置 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`。
4. 嘉宾必须先在小程序会务安排页点击“开启提醒”；每次授权通常只允许发送一次，发送后需再次授权。
