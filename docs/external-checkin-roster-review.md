# 外部签到名单重复确认与手动录入

## 本次需求

预检不能只显示“核验字段相同”的笼统错误。管理员需要看到每组重复的完整记录、来源行号和差异列，并选择保留哪条。后台同时支持单独手动添加一位嘉宾的名单资料。

## 操作约定

- 按当前会议配置的核验字段组合精确分组，文本规范化规则保持不变。
- 每组显示已有名单与文件中所有重复记录，标明核验列、差异列及已有签到时间。大批数据分页展示，始终可查看全部候选记录。
- 内容完全相同的重复自动去重；有差异的重复展示完整对比，管理员可保留一条或删除本次导入候选。详见 [后续名单操作规则](external-checkin-roster-actions.md)。
- “保留这条”只更新当前窗口的选择；关闭或取消窗口不会写入。只有全部重复组已处理且格式错误为零，才允许提交。
- 选中已有记录会跳过本组导入记录；选中文件/手动录入记录会新增，或更新本组已有记录的名单资料。已有 ID、首次签到时间、现场填写资料都保留。
- 预检摘要绑定会议、版本、原始行、来源行号和被比较的既有记录及签到状态。提交时重新计算并检查候选成员，拒绝未处理、伪造或已过期的选择；写入在现有事件锁和事务内完成。
- 文件里的空白行不参与导入，但保留真实工作表行号用于定位。字段列名展示会议配置及文件映射列。
- “手动添加”按当前会议字段显示表单；核验字段必填，其余选填。无重复时点击保存直接完成；有差异时先对比选择，再确认保存；完全一致时自动去重。

## 验证范围

共享规则验证同文件重复、已存在记录重复、完全重复、三条以上候选、非法/漏选、格式错误和统计；API 验证整批原子写入、权限、摘要篡改、过期预检、签到状态保留及手动录入。浏览器验收导入对比、差异列、逐组保留、取消不写入、手动新增及重复处理。

不增加数据库结构，不修改原会议报名、订单或支付流程。发布需要同时更新 API、共享模块和后台。

## 首次发布时的本地验证结果

- 共享规则与表格解析：43 项测试通过，包含空白行后的真实行号与重复选择校验。
- 真实 NestJS + PostgreSQL：14 项测试通过，包含整批写入、手动录入权限、候选篡改、预检过期及首次签到状态保留。
- 后台类型检查、后台构建、API 构建通过。
- 使用合成数据进行浏览器验收：手动新增、手动重复更新、差异列对比、逐组选择、取消不写入及导入后名单统计均通过。

人工验收入口：进入外部会议的“管理签到”，在“嘉宾名单”使用“手动添加”，或“导入名单 → 预检导入 → 保留这条 → 确认导入”。
