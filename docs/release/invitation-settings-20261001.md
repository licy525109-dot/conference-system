# 公众号配置与外部会议发布

## 授权与基线

- 用户已明确授权直接上线，沿用现有 PR、质量检查和生产自动部署流程。
- 基线：`795b3d7a687777962dfe6cf841e1cd53015fd4ff`，上一版邀请函 PR #96。
- 发布分支：`codex/invitation-wechat-external-registration`。
- 隔离发布不包含原工作区未发布的 CMS 改动、本地账号、公众号密钥、上传文件或业务数据。

## 发布范围

- 后台公众号 AppID/AppSecret、启停、连接检测、域名校验文件，独立 `invitation:settings` 权限。
- 配置密钥使用既有 AES-256-GCM 加密方法，仅服务端解密，不通过 API 或审计回显。
- 新建邀请函可选择系统会议或独立外部会议，不建立占位 Conference。
- 报名入口支持小程序会议、外部 HTTPS 链接或隐藏，发布后旧个人链接同步。
- 外部链接不携带个人信息或邀请标识；外部表单提交不自动写入系统报名或支付记录。
- 未修改支付金额、回调验签、订单成功规则、退款或通知核心逻辑。

## 数据库与回退边界

- 增量迁移：`20261001160000_invitation_external_registration`。
- `invitation_campaigns.conferenceId` 改为可空，新建 `invitation_wechat_configs` 表；无删除数据操作。
- 生产由现有部署脚本先备份数据库、环境和静态文件，再迁移与重启。
- 已创建独立外部会议后，不能直接回退到假定会议关联非空的旧代码；需保留空关联兼容逻辑。
- 不删除外部会议、不删配置表、不强制恢复非空约束，不恢复旧数据库覆盖后续业务写入。
- 保留服务器既有加密密钥及备份；更换密钥需保留旧密钥解密兼容。

## 发布前验证

- 原工作区：邀请函浏览器回归 38 项通过；新旧真实 API 集成测试通过；真实本地工作人员登录和手机面板通过。
- 隔离发布工作树：全项目类型检查、单元测试、权限扫描和 `git diff --check` 通过。
- PR 阶段继续运行既有质量工作流：lint、测试、API/Admin/H5/小程序构建与浏览器回归。
- 合并后继续运行既有部署预检与生产部署工作流，不绕过质量检查。

## 上线后验收

1. 检查生产提交、迁移完成状态、API readiness、PM2 与数据库备份元数据。
2. 检查公众号配置和报名选项接口未登录返回 401，配置密钥不公开。
3. 检查品牌域名的校验文件路由、后台新组件资源和公开邀请函资源。
4. 后台重新登录后打开「公众号配置」，由用户自行输入凭据、上传微信校验文件并完成公众平台配置。
5. 用户创建外部会议、填入报名地址，保存并发布，使用手机验证原邀请链接报名跳转。

真实公众号连接和微信分享需要用户配置后验收，不以本地模拟测试代替；生产验收不插入演示记录、不发送消息或发起支付。
