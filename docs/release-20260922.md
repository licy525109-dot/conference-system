## Deployment gates

1. Push release branch and pass GitHub PR quality checks before merging to main.
2. Use the existing production deployment workflow. It backs up the database,
   environment and static files before applying migrations and restarting API.
3. Verify public health, new schema, deployed commit and static assets afterward.
4. Upload the production Mini Program build through the authenticated developer
   tool. Upload is not review submission or publication.
5. Keep `REGISTRATION_PROFILE_REQUIRED=false` until the compatible Mini Program
   is officially available. Do not block guests using the old published client.
6. Keep `ADMIN_PAID_ALERT_WORKER_ENABLED=false` until recipients are confirmed
   and a controlled end-to-end notification has been accepted.

## Still requires acceptance

while retaining new tables/columns. Do not blindly restore the pre-release
